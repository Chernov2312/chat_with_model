# API

Документ описывает маршруты, зарегистрированные текущим приложением FastAPI.
Интерактивная OpenAPI-документация доступна по адресу `http://localhost:8000/docs`
после запуска backend.

## Общие сведения

- Базовый префикс API: `/api/v1`.
- Для защищённых маршрутов передавайте заголовок
  `Authorization: Bearer <access_token>`.
- Данные API передаются и возвращаются в JSON, кроме потокового ответа чата
  (Server-Sent Events, SSE).
- CORS разрешает frontend-origin `http://localhost:5173` и
  `http://127.0.0.1:5173`.

## Авторизация

### Регистрация

`POST /api/v1/auth/register`

Запрос:

```json
{
  "username": "alice",
  "email": "alice@example.com",
  "password": "example-password"
}
```

`username`: от 3 до 50 символов; `email` должен быть корректным адресом;
`password`: от 8 до 250 символов. При успешной регистрации возвращается
`201 Created` и объект пользователя с токеном доступа:

```json
{
  "id": "uuid",
  "username": "alice",
  "email": "alice@example.com",
  "access_token": "…",
  "token_type": "bearer"
}
```

### Вход

`POST /api/v1/auth/login`

Формат тела: `application/x-www-form-urlencoded`, поля `username` и `password`.
Поле `username` в текущем интерфейсе заполняется email; backend ищет пользователя
по username или email. Успешный ответ содержит access token.

## Пользователь

Все маршруты требуют access token.

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/api/v1/users/me` | Получить ID, username и email текущего пользователя |
| `PATCH` | `/api/v1/users/me` | Обновить email |

Тело `PATCH`:

```json
{
  "email": "new-address@example.com"
}
```

## Сессии чата

Для всех маршрутов сессий требуется access token. В настоящее время при создании
сессии сервер автоматически создаёт или повторно использует привязанную к
пользователю запись `GigaChat-3-Ultra`. Выбор других моделей через API не
реализован; поле `model` в запросе создания принимается схемой, но не определяет
используемую модель.

### Создать сессию

`POST /api/v1/sessions` — `201 Created`.

```json
{
  "model": "GigaChat-3-Ultra",
  "system_prompt": "Ты полезный ассистент.",
  "temperature": 0.7,
  "max_tokens": 2048
}
```

`max_tokens` необязателен и по умолчанию равен `2048`. Ответ включает ID сессии,
ID владельца и модели, настройки и время создания.

### Получить список сессий пользователя

`GET /api/v1/sessions` возвращает массив сессий текущего пользователя.

### Получить сессию

`GET /api/v1/session/info/{session_id}` возвращает одну сессию. Если сессия не
найдена у текущего пользователя, возвращается `404 Not Found`.

### Получить историю сообщений

`GET /api/v1/sessions/{session_id}/messages` возвращает:

```json
{
  "messages": [
    {
      "id": "uuid",
      "role": "user",
      "content": "Привет!",
      "created_at": "2026-01-01T12:00:00Z"
    }
  ]
}
```

История сортируется по `created_at` по возрастанию, затем ограничивается первыми
50 записями. Пагинации пока нет. Доступ выбирается по ID сессии и пользователя.

### Удалить сессию

`DELETE /api/v1/sessions/{session_id}` возвращает `204 No Content`; если сессия
не найдена у пользователя — `404 Not Found`.

## Сообщения и потоковая генерация

`POST /api/v1/sessions/{session_id}/messages/stream` — защищённый SSE endpoint.
Запрос:

```json
{
  "content": "Расскажи короткую историю",
  "stream_options": {}
}
```

`stream_options` — объект со значениями типа boolean; интерфейс отправляет пустой
объект. Роль задаёт backend: входящее сообщение сохраняется как `user`, ответ —
как `assistant`. Системный промпт сессии добавляется в начало контекста модели.
Поля `temperature` и `max_tokens` сохраняются в сессии, но пока не передаются
GigaChat при генерации.

Поток содержит события `token` с частями ответа и завершающее событие `done`
с данными `[DONE]`. Перед генерацией backend проверяет, что сессия принадлежит
пользователю. Текущая модель — `GigaChat-3-Ultra`.

## Хранение данных и ограничения

Используются таблицы `users`, `models`, `sessions` и `messages`. Пароли
хранятся в виде хеша. У сессии есть владелец, ID модели, системный промпт,
температура, лимит токенов, заголовок и признак архивации. Сообщение связано с
пользователем и сессией, содержит роль, текст и необязательное число токенов.

При старте `Base.metadata.create_all()` создаёт отсутствующие таблицы, но не
мигрирует уже созданные. При изменении схемы существующей БД потребуется
миграция либо отдельное пересоздание базы.
